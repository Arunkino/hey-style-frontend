# HeyStyle favicons & app icons

Everything in [`public/favicon/`](../../public/favicon/) plus
[`public/favicon.ico`](../../public/favicon.ico) is generated by `gen.mjs`.
Don't hand-edit those files — regenerate them:

```
npm install --no-save sharp png-to-ico
node brand/icons/gen.mjs
```

`--no-save` keeps the two tools out of `package.json` — they are build-time
only and the site never ships them.

## Why this exists

The previous set was exported straight out of a design tool. Every file had the
**layout grid and the S path's bezier anchor points baked into the pixels**, and
the purple artboard stopped short of the square canvas, leaving transparent bars
down both sides. Google shows favicons as a circle in search results, so it
cropped that straight into the result row for heystyle.in.

## Files

| File | Use |
|---|---|
| `favicon.ico`, `/favicon.ico` | 16 / 32 / 48px. Browser tabs, bookmarks, and the root path crawlers probe blind. |
| `favicon-96x96.png` | Google's search-result favicon. |
| `favicon.svg` | Vector tab icon for browsers that take one. |
| `apple-touch-icon.png` | 180px. iOS home screen. |
| `web-app-manifest-192x192.png`, `-512x512.png` | Manifest `purpose: "any"`. |
| `web-app-manifest-maskable-512x512.png` | Manifest `purpose: "maskable"`. |

## Rules baked into `gen.mjs`

- **Full bleed, no transparency.** iOS composites a transparent app icon onto
  black; Google and Android just crop it. The purple runs to all four edges.
- **Square, and 48-divisible where Google looks.** Google ignores a favicon that
  isn't square, and wants a side that's a multiple of 48.
- **The mark stands at 62% of the canvas**, not the 89% the old files used. The
  search-result circle is inscribed in the full width, so a taller mark gets its
  tips clipped and reads as cramped.
- **The maskable icon drops to 50%.** Android may keep only the centre 80% and
  can mask it round. A mark this tall and narrow needs more margin than the
  usual 66% guidance gives it.
- **Black on `#8E6EE8`.** That's 5.5:1; a white mark on the same purple would
  only reach 3.8:1 and mush at 16px.
- **Rasterised from a 4x master.** Asking an SVG renderer for 16px directly
  loses the thin tips of the swoosh.

The `S` is read from [`../qr/s-path.txt`](../qr/s-path.txt) — the same file the QR
badge uses, so the icon, the QR mark and the site wordmark can't drift apart.

## After deploying

The `<link>` hrefs carry `?v=2` so browsers drop the cached old icon immediately.
Google is slower: it re-fetches favicons on its own recrawl schedule, so the
search result can keep showing the old icon for days or weeks. Requesting
indexing for `https://heystyle.in/` in Search Console nudges it along.
